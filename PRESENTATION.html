LoreLock: Story Continuity AI Agent

A lightweight assistant that remembers approved story facts and flags possible contradictions in new draft scenes.

Student: [Your Name] Streamlit prototype Human-approved memory

Problem

Long stories create a continuity memory burden.

What changes during drafting

Relationships, secrets, names, locations, timelines, object ownership, character status, and world rules.

What goes wrong

A character knows a secret too early, a destroyed object reappears, or a renamed location drifts between drafts.

Target users

Fiction writers, editors, beta readers, writing students, and small story teams.

Project scope

The system flags risks. It does not rewrite scenes or decide whether a contradiction is intentional.

Agent Goal

Protect story consistency while keeping the writer in control.

01 Read text

User submits story material, lore notes, or a new draft scene.

02 Extract facts

LLM provider or local fallback proposes structured continuity facts.

03 Approve memory

The user reviews, edits, and accepts only facts that should become canon.

04 Check scene

Relevant approved memory is compared against the submitted scene.

05 Report risks

Warnings include evidence, severity, line references, and next actions.

Design Choice

AI extraction, deterministic judgment.

  • Provider output must be JSON, grounded, atomic, and normalized.
  • Facts pass through validation before they can become memory.
  • Continuity warnings are produced by explainable Python rules.

System Architecture

A local Streamlit app with modular Python services.

Interface

app.py starts the app. src/ui.py handles the Streamlit workflow, provider controls, and memory editing.

Reading engines

Supports Ollama, Gemini, Claude, OpenAI-compatible APIs, and a private heuristic fallback.

Extraction

src/extraction.py infers metadata, chunks input, calls providers, and recovers missed lines.

Facts

src/facts.py creates, validates, deduplicates, and canonicalizes fact objects.

Memory

Approved facts are saved locally as JSON in the selected project folder.

Checker

src/continuity.py detects conflicts, risks, identity drift, and setting drift.

What LoreLock Detects

Warnings are specific, explainable, and reviewable.

  • Relationship conflicts: wife versus girlfriend, friend versus enemy.
  • Fact conflicts: status, trait, ability, possession, or lifecycle changes.
  • Knowledge leaks: a character knows information before the approved reveal point.
  • World-rule risks: a scene touches a topic governed by a restrictive rule.
  • Drift checks: possible identity drift or setting drift across drafts.
  • Same-scene contradictions: contradictions inside the submitted text even when memory is empty.

Implementation

Lightweight by design.

  • Built with Python and Streamlit.
  • Only listed runtime dependency is streamlit>=1.35.
  • Provider calls use standard-library HTTP utilities.
  • Extraction depth supports Quick, Standard, and Deep review modes.
  • Local files store memory and provider settings under user control.

Testing

The prototype has automated verification.

33 tests passed in the most recent verification run.

Coverage areas

Scene review workflow, empty-memory review, relationship logic, identity drift, setting drift, provider settings, fallback extraction, and coverage backfill.

Responsible AI

The system treats AI output as candidate evidence, not truth.

Privacy

External providers receive submitted text. Users can choose local Ollama or heuristic fallback for stronger privacy.

Hallucination control

LLM facts are parsed, normalized, grounded in evidence, and approved before memory storage.

Human control

Warnings are review prompts, not automatic edits or final judgments.

Known limits

Extraction can miss subtle facts, cultural naming patterns, indirect reveals, or intentionally ambiguous writing.

Conclusion

LoreLock demonstrates a practical agentic workflow for creative writing.

  • It perceives story text and extracts structured continuity facts.
  • It retains approved memory across interactions.
  • It applies deterministic rules to produce explainable warnings.
  • Future work: SQLite memory, relationship graph view, batch chapter ingestion, stronger alias handling, and vector search.
